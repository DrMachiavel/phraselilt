# Architecture

A small Swift package: `PracticeCore`, a SwiftUI/AppKit menu-bar app, and the developer-only `SpeechProbe`. No server or plugin system. `Recording`, `Transcribing`, `ListeningAudio`, `ReferenceSpeaking` and `InputActivityReading` provide replaceable boundaries.

`PracticeSession` serializes recording and processing on the main actor. Original audio, raw recognition, intended wording, confirmation, source label, timing and reference variety remain separate. Transcription results carry clip ID, revision UUID and variety. Selection, edits, deletion, reference changes and replacement cancel/invalidate stale work. Optional capture-source and practice-segment fields decode older history without a migration. New clips use the full recognition result. On launch, untouched legacy automatic excerpts expand to the full raw transcript with confirmation reset; explicit wording corrections remain intact. Original audio and raw recognition are never rewritten. Retry recordings retain intended wording and a group ID independently of recognition.

`CoreAudioInputActivity`, `CapturePolicy` and `Companion` follow selected input activity without any keyboard hook. The pure policy handles baseline/idle requirements, source ownership, self-exclusion and device changes. The controller gates queued work with a generation token, tolerates brief activity dropouts, and cancels safely on pause or uncertainty. See COMPANION.md for scope and compatibility limits.

`MicrophoneRecorder` requests permission only from an explicit manual action or previously enabled companion scope. Automatic capture has both a 30-second recorder limit and session deadline; manual practice is bounded below 60 seconds. Recorder delegate callbacks verify recorder identity before finishing or cancelling a session. Input changes, sleep and session interruptions stop recording. No global shortcuts, Accessibility monitor, system audio tap or default-device/rate mutation are installed.

`Listening` provides separate cancellable reference and recording actions. Reference playback never starts the user recording automatically. Each operation checks its generation before updating state, so switching actions cannot apply stale completion or errors. `Playback` binds synthesis callbacks and cancellation to an utterance/operation identity and resumes completion continuations exactly once. Playback is stopped before capture, selection, deletion, wording or reference changes.

`ClipStore` uses private UUID filenames, validated/copied imports, atomic JSON writes and a 100-clip cap. Corrupt indexes fail closed. Startup removes unindexed temporary audio; deletion removes managed audio before metadata. Retention runs on launch, settings changes and hourly when not recording. Disk failures stay visible and retryable; no secure-erasure claim.

An AppKit-owned `NSStatusItem` opens one transient `NSPopover` anchored beneath PL. SwiftUI renders both practice and inline Settings/Back within a fixed, scrollable 390 × 540 pt surface. There is no detached practice window, separate Settings scene, Dock window or Open Practice step. Clicking PL toggles the popover; clicking outside dismisses it and stops playback. Background capture and transcription never open or activate it. Explicitly reopening the app shows the same anchored popover. The native Edit menu retains standard text-editing keyboard shortcuts.

Audio and transcripts are never logged by the app. The developer probe deliberately prints synthetic file-transcription results, while its activity-observation mode prints metadata only.

The optional `SoundHints` coordinator binds automatic acoustic checks to a cancellable generation. `LocalSoundAssessor` is a serial actor with a two-thread native ONNX session, maximum six short word windows, and at most two tentative targets. It uses original waveform input and greedy phone decoding, never recognized-word identity as evidence. Provisional displayed wording and same-count corrections reuse approximate ASR windows; a matching following acoustic phone sequence is required independently. Changed counts, unsupported words/reference varieties, missing timings and weak evidence abstain. Results remain in memory and invalidate on relevant review/capture changes. The reference voice never feeds a similarity score. `SoundModelSetup` is the only app download path; it fetches two immutable checksummed files only after the explicit setup action.

`AppModel` observes session changes and sound-model readiness on the main run loop, after published session mutations settle, and synchronizes `SoundHints` independently of popover visibility. Its explicit request context deduplicates unchanged inference and invalidates stale results. Recording/preparation blocks analysis until the new clip is ready. The renderer also compares the full context before displaying highlights, so a stale range cannot appear on another clip during an asynchronous update. Compound/chunk runs contribute text tokens to matching but never fabricate sound boundaries inside those runs.
